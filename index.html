From the first login test to the last regression run before release. Pick the layer, I'll cover it.

REST and GraphQL suites in Ruby with Cucumber, Postman and Swagger. I also use the API to seed test data, like a live auction, so UI tests start from a known state.

Visual and network checks

Visual regression catches the layout bugs assertions miss. Network-log checks catch the wrong call behind a screen that looks right.

AI-assisted test design, with guardrails

I turn test designs into test specs with AI, and every generated step is checked against real screen objects, so it can't invent a locator that doesn't exist.

// test design → spec
it('buys a highlight package for an active ad', async () => {
  await LoginFlow.asSeller();
  await MyAdsScreen.open(ad.id);
  await PackageFlow.buy('highlight');
  // guardrail: locator must exist in screen objects
  await expect(MyAdsScreen.badge('Highlight')).toBeDisplayed();
});

From spec to green build in three steps

  1. 1

    Read the risk

    I turn the PRD into a test plan and start with the flows that cost money when they break: login, posting, payment.

  2. 2

    Automate the right layer

    API for test data, UI for user journeys, data-driven cases for the edges. Every case is traced back to Jira.

  3. 3

    Gate every build

    Smoke on each build, regression on real devices before release. A flaky test gets fixed, not retried until it passes.
